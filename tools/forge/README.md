# forge — the Lantern build-inliner

`forge` is a tiny, **zero-dependency** Node ESM script (only `node:fs` / `node:path`)
that turns a tale's source template into a **self-contained, double-clickable HTML
file** — the engine and the world inlined, no network, no dependencies.

It is the build step the Lantern spec defers to (see `adventure/ADVENTURE.SPEC.md`
§7). It runs **author-side only**: visitors still open one dependency-free file.

## Why a build step doesn't break "no build for visitors"

The workshop ships **self-contained** artifacts. But "self-contained" is a property
of the **shipped file**, not of the authoring process. Without forge, the only way to
keep the engine inlined in every tale is to **copy the engine into every tale by hand**
— which forks the engine: fix a bug in one tale and the others rot.

forge fixes that. The engine lives in **exactly one canonical place**
(`adventure/engine/lantern.js`); each tale's `.src.html` *references* it with a
directive; forge inlines it at build time. One engine, inlined everywhere, no fork —
and the emitted `.html` is exactly as self-contained as a hand-inlined one (engine +
world inlined, zero deps, zero network, double-clickable). The pipeline is:

```
sources (engine/*.js, worlds/*.js) + <tale>.src.html  ──forge──▶  <tale>.html  (shipped)
```

## The directive

Inside a `.src.html`, an HTML comment on its own line marks an inline slot:

```html
<script>
<!-- forge:include engine/lantern.js -->
</script>
```

- One directive per line.
- `<relpath>` resolves **relative to the `.src.html`'s own directory**. So
  `adventure/the-lamplighter.src.html` with `<!-- forge:include engine/lantern.js -->`
  pulls `adventure/engine/lantern.js`.
- forge replaces the directive line with the included file's contents.
- For included **`.js`** files, forge strips the dual-use module guard
  (`if (typeof module !== 'undefined' && module.exports) { … }`) and any leading
  `export ` keyword, so the inline is clean in a browser. (The guard is inert in a
  browser anyway; this is just tidiness.) Non-`.js` includes are inlined verbatim.

### Inline directives (`forge:asset`, `forge:json`)

`forge:include` owns its whole line. Two further directives are **inline** — they are
substring tokens, so they splice a value into the middle of a line the author wrote
(and multiple may share one line). They fold a page's own binary + data so it stays
self-contained:

```html
<audio src="<!-- forge:asset piece.mp3 -->" controls></audio>
<script>const TIMING = <!-- forge:json piece.json -->;</script>
```

- **`forge:asset <relpath>`** reads the sibling as **binary**, base64-encodes it, and
  emits the *bare* `data:<mime>;base64,…` string (the author owns the surrounding
  quotes/element, so it also drops into CSS `url(…)` or a future `<img src>`). The MIME
  comes from a frozen allow-table: `.mp3 .wav .ogg .m4a` (audio), `.png .jpg .jpeg
  .gif .svg .webp` (image). An unknown extension is a hard error.
- **`forge:json <relpath>`** `JSON.parse`s the file to validate it (a build error on
  bad JSON) then emits its **original text verbatim** — a pure passthrough, not a
  re-serialize, so `--check` sees no drift.
- The fold is a pure function of the asset's bytes → single-line ASCII, so `--check`
  catches a stale page (a tampered asset byte turns it red), and the inlined blob
  decodes byte-identical to the source. An inline directive inside an **included**
  partial folds too.
- **Size policy** (on the encoded length): over **4 MiB** → a `⚠` warning, shipped
  anyway by default (`--strict` makes it fatal); over **24 MiB** → always fatal.
- A page may carry *only* inline directives (no `forge:include`) and still be valid.

## The banner

forge stamps the very top of the output (right after `<!doctype html>`) with a
generated-file banner, including the engine version it read from `LANTERN_VERSION`:

```html
<!-- GENERATED BY forge — do not edit directly. Edit the .src.html + the included
     sources, then re-run: node tools/forge/forge.mjs <thisfile>.src.html. Engine: lantern vX.Y -->
```

**Edit the `.src.html` and the included sources — never the generated `.html` directly.**

## Usage

```bash
# Build one or more named source files → sibling .html
node tools/forge/forge.mjs adventure/the-lamplighter.src.html
node tools/forge/forge.mjs adventure/a.src.html adventure/b.src.html

# Build every *.src.html under a root (recursive; default root = git/repo root).
# Skips .git and node_modules.
node tools/forge/forge.mjs --all
node tools/forge/forge.mjs --all adventure

# Check for drift: build in memory, diff against the on-disk .html.
# Exit 1 if any shipped file is stale (or missing); exit 0 if all current.
node tools/forge/forge.mjs --check adventure/the-lamplighter.src.html
node tools/forge/forge.mjs --check --all

# --strict (BUILD or --check): treat an oversized-asset WARNING as a failure.
# Default ships a >4 MiB asset with a ⚠; --strict refuses it (a pre-ship gate).
# The 24 MiB hard ceiling is fatal regardless of --strict.
node tools/forge/forge.mjs --check --strict --all

# Help
node tools/forge/forge.mjs --help
```

`--check` is the staleness guard: run it (e.g. in a pre-ship sweep) to prove every
shipped `.html` matches a fresh build of its `.src.html` + sources. If someone edits
the engine but forgets to re-forge a tale, `--check` catches it.

## Errors

forge fails with a helpful message and a nonzero exit (never a raw stack) on:
a missing input, an input that isn't `*.src.html`, a `forge:include` /
`forge:asset` / `forge:json` target that doesn't exist, or a `.src.html` with no
directives at all. The inline directives add three more: a **`forge:asset`** with an
**unknown extension** (error lists the allow-table), an asset **over the 24 MiB hard
ceiling** (always fatal) or over the 4 MiB warn line under **`--strict`**, and a
**`forge:json`** pointing at **invalid JSON**. A failed build also surfaces in
`--check` (a per-file "build error" → nonzero exit), so a missing/oversized/invalid
asset is caught by a pre-ship sweep for free. forge handles CRLF/LF, multiple
directives, and a missing trailing newline, and always emits a single trailing
newline.

## Authoring a new tale (the short version)

1. Write `worlds/<id>.js` (copy `worlds/_template.js`); get the in-page / Node
   self-test green.
2. Copy `adventure/the-lamplighter.src.html` → `adventure/<id>.src.html`; swap the
   world include to `<!-- forge:include worlds/<id>.js -->`; set the accent + title.
3. `node tools/forge/forge.mjs adventure/<id>.src.html` → emits `adventure/<id>.html`.
4. Add the tale to the shelf in `adventure/index.html`.

See `adventure/ADVENTURE.SPEC.md` §6 for the full authoring guide.
